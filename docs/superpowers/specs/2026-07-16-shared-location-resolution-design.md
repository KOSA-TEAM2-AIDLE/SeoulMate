# 공통 위치 해석 설계

## 목표

`POST /chat`으로 들어온 일반적인 위치 표현을 도메인 검색 전에 해석하되, `TravelQueryStartRequest`, `StructuredTravelQuery`, `/chat` 요청 및 응답 계약을 변경하지 않는다. 관광·식당·카페·숙소 검색기는 동일하게 확정된 기준 좌표를 전달받고, 각 도메인은 자신의 검색 조건 해석에만 집중한다.

## 호환성 원칙

- `TravelQueryStartRequest`와 `StructuredTravelQuery` 필드를 추가·삭제·변경하지 않는다.
- 기존 `filters.location`, `filters.radius_km`, 요청의 `lat`, `lng`, `location_name`을 사용한다.
- 해석된 좌표는 기존 `DomainSearchRequest.latitude`, `longitude`, `location`, `radius_km`로 전달한다.
- 위치 해석 내부 상태와 장소 후보는 외부 API 스키마에 노출하지 않는다.
- 위치 해석 실패는 도메인 검색 자체의 실패로 바꾸지 않는다. 경고를 남기고 기존 위치 없는 검색 흐름을 유지한다.

## 책임 경계

### 구조화 단계

기존과 같이 질문에서 도메인 작업과 `filters.location`, `filters.radius_km`을 생성한다. 위치 후보 조회나 좌표 확정은 담당하지 않는다.

### 공통 위치 해석 단계

`RecommendationOrchestrator`가 도메인 검색 요청을 만들기 전에 실행한다.

- `filters.location`이 있으면 `PlaceResolver`로 서울 장소를 조회한다.
- 현재 위치 표현이면서 요청 좌표가 있으면 외부 장소 조회 없이 해당 좌표를 사용한다.
- 명시적 장소명과 사용자 좌표가 함께 있으면 사용자 좌표를 Kakao Local 검색의 중심 좌표로 전달한다.
- 장소가 하나로 확정되면 이름과 좌표를 모든 관련 도메인 작업에 공유한다.
- 같은 기준 장소를 한 요청 안에서 반복 조회하지 않는다.
- `filters.radius_km`이 없으면 도메인별 기본 반경 정책을 적용할 수 있도록 `None`을 유지한다.

### 도메인 검색기

공통 계층이 전달한 기준 좌표를 사용한다. 관광 검색기는 카테고리·행사 기간·반경·거리 계산을 담당하며, 시설명 추출이나 Kakao Local 호출을 다시 수행하지 않는다. 식당·카페·숙소도 동일한 위치 계약을 사용할 수 있다.

## 위치 판정 규칙

### 사용자 현재 위치

다음과 같은 표현에서 구조화 결과의 위치가 비어 있고 요청에 `lat`, `lng`가 있으면 사용자 좌표를 기준으로 한다.

- 내 근처, 내 주변
- 여기 근처, 여기 주변
- 현재 위치에서, 현재 위치 기준

좌표가 없으면 기존 HITL 흐름에서 기준 지역 또는 현재 위치 제공을 요청한다.

### 명시적 기준 장소 또는 지역

구조화 결과의 `filters.location` 값을 그대로 장소 조회어로 사용한다. 예시는 `경복궁`, `서울시청`, `종로구`, `홍대`다. 공통 계층은 원문을 다시 정규식으로 광범위하게 분해하지 않는다. 이는 기존 구조화 출력과 판단이 충돌하는 것을 방지한다.

### 불명확한 관계

`롯데호텔 카페`, `서울역 맛집`처럼 장소와 검색 대상의 관계가 불명확하면 공통 계층이 원문만 보고 새 위치를 만들어내지 않는다. `filters.location`이 구조화되어 있을 때만 위치로 해석하고, 그렇지 않으면 도메인 검색어로 유지한다.

## 장소 후보와 HITL

`PlaceResolver` 결과가 하나이면 즉시 사용한다. 정확히 하나를 선택할 수 없고 후보가 여러 개면 도메인 검색을 실행하지 않고 최대 3개의 후보 이름과 주소를 기존 채팅 연속 처리 상태에 저장한다. 사용자는 같은 `travel_query_thread_id`로 후보를 선택하며, 선택된 좌표로 검색을 재개한다.

후보가 없으면 위치를 더 구체적으로 입력해 달라는 기존 언어 정책에 맞춘 질문을 반환한다. 한국어 질문에는 한국어, 영어 질문에는 영어를 사용한다.

## 관광 거리 검색

- 기준 위도와 경도가 모두 있을 때만 거리를 계산한다.
- 후보 좌표와 기준 좌표 사이의 Haversine 거리를 `distance_km`로 기록한다.
- 명시적 반경 또는 기본 반경 밖 후보를 제외한다.
- 위치 기반 검색에서는 좌표가 없는 후보를 제외한다. 위치 조건이 없는 일반 검색에서는 유지한다.
- 반경 내 후보는 카테고리 일치와 벡터 유사도를 유지하면서 거리 점수를 보정한다.
- 종료일이 기준일보다 이전인 행사는 거리와 무관하게 제외하고, 종료일이 없는 행사는 유지한다.

## 오류 처리

- 위도와 경도 중 하나만 있으면 기존 입력 검증 오류로 처리한다.
- Kakao API 키 누락·타임아웃·응답 오류는 위치 해석 경고로 변환하고 검색은 위치 없이 계속한다.
- 서울 밖 후보는 기존 `PlaceResolver` 정책대로 제외한다.
- 잘못된 후보 선택은 다시 후보를 요청하며 임의의 첫 번째 후보를 사용하지 않는다.

## 테스트 기준

- 기존 요청·구조화 스키마 직렬화 결과가 변경되지 않는다.
- `내 근처 전시회`는 요청 좌표를 사용하고 Kakao 조회를 하지 않는다.
- `경복궁 근처 전시회`는 경복궁 좌표를 관광 검색 요청에 전달한다.
- 동일 장소를 사용하는 관광·식당 복합 질문은 장소를 한 번만 해석한다.
- 다중 후보는 검색을 실행하지 않고 HITL 후보 선택으로 전환한다.
- 위치 API 장애 시 위치 없는 검색으로 안전하게 진행한다.
- 관광 후보는 반경 밖, 좌표 없음, 종료 행사를 제외한다.
- 거리 정보가 결과 메타데이터에 포함되고 가까운 후보가 합리적으로 우선된다.

## 범위 제외

- 구조화 프롬프트나 공용 API 스키마의 전면 개편
- 모든 자연어 위치 관계를 정규식으로 직접 추출하는 기능
- Kakao Local MCP 서버를 내부에서 HTTP로 재호출하는 구조
- 서울 외 지역 검색 지원
