# 관광 추천 지역 필터 및 표시 언어 설계

## 범위

- 관광 도메인의 검색, DSPy 선택/렌더링, 관련 테스트를 수정한다.
- 공용 프론트에서는 장소 추천 카드의 표시 전용 변환만 수정한다.
- 식당, 카페, 숙소의 검색/추천 로직과 API 계약은 변경하지 않는다.

## 지역 필터

관광 후보는 명시 위치가 있을 때 다음 순서로 제한한다.

1. 위치를 지오코딩해 좌표를 얻는다.
2. 후보 좌표에 반경 제한을 적용한다. 명시 반경이 없으면 관광 도메인의 기본 반경을 사용한다.
3. `address_matches_search_area()`로 요청 권역과 후보 주소의 자치구가 명백히 충돌하는 후보를 제거한다.

주소 또는 권역을 판별할 수 없는 경우에는 해당 조건만 통과시켜, 데이터 결손 때문에 모든 후보가 사라지지 않게 한다.

## 관광 답변과 사이드 패널

DSPy 구조화 답변의 장소별 추천 문단을 하나의 렌더링 함수에서 만든다.

- 채팅은 장소 순번과 이름 뒤에 이 문단을 표시한다.
- 사이드 패널은 카드 제목이 장소명을 이미 표시하므로 같은 문단만 표시한다.
- 문단에는 질의 적합성, 혼잡도, 날씨를 문장으로 자연스럽게 포함한다.
- 기계적인 `질의 적합성: ... / 혼잡도: ... / 날씨: ...` 라벨 연결은 제거한다.

## 언어

- 관광 후보 검색과 DSPy 렌더링은 `StructuredTravelQuery.language`를 단일 기준으로 사용한다.
- EN 요청은 영문 관광 데이터와 영문 추천 문장을 사용하고, KO 요청은 한국어를 사용한다.
- 프론트의 탭 전환은 카테고리와 고정 UI 레이블을 즉시 KO/EN으로 바꾼다.
- 이미 저장된 자유형 추천 문장과 장소 설명은 탭 전환만으로 기계 번역하지 않는다. 새 요청의 언어가 해당 문장의 언어를 결정한다.

## 관측 시각

혼잡도와 날씨의 관측시각은 채팅과 사이드 패널 모두 `YYYY-MM-DD HH:mm`으로 표시한다. 원본 ISO 8601의 초와 UTC 오프셋은 노출하지 않는다. 파싱할 수 없는 값은 원문 대신 시각 정보를 생략한다.

## 검증

- 경복궁/종로구 요청에서 송파구 후보가 제외되는 회귀 테스트
- 좌표 반경과 주소 권역이 함께 적용되는 테스트
- KO/EN 각각에서 채팅 문단과 사이드 패널 사유가 같은 본문을 사용하는 테스트
- KO/EN 관측시각 형식 테스트
- 프론트 탭 전환 시 카테고리와 고정 레이블이 즉시 바뀌는 테스트
